在 fashion-imagegen 项目（C:\Users\Administrator\fashion-imagegen）实施修复，解决 Codex 失败触发 Seedream fallback 时任务被卡住/重试计数错误消耗的问题。严格只改 app/queue/worker.py 一个文件。

【修改1】_process_master 的 except 块（约544-551行）删除 _fail_safely 调用，直接进 Seedream fallback：
```python
except (RuntimeError, RecoveryError) as exc:
    logger.warning(
        "Codex generation failed for %s, will attempt Seedream fallback: %s",
        task_id, exc,
    )
    recovered = None
```
（删除 await self._fail_safely(task_id, str(exc)[:4000]) 这一行）

【修改2】_recover_generation 新增 allow_retry 参数（默认 True），各失败分支在 allow_retry=False 时只 return None 不调 _retry_or_finalize：
- 函数签名加 allow_retry: bool = True
- 在 result.failure_reason 分支（约222-231行）、no thread_id + hard timeout 分支（约236-241行）、grace recovery 失败分支（约292-296行）、deadline 超时分支（约304-308行）中，当 allow_retry=False 时直接 return None（跳过 _retry_or_finalize）
- 注意：soft_timed_out/rc!=0 分支的 WAITING_RECOVERY transition 和 recovery.recover() 保留（因为 recovery 可能成功）
- _process_master 调用处（约539行）传 allow_retry=False
- _process（标准模式）调用处保持默认 True

【修改3】_generate_master_seedream 兼容 RUNNING 状态转换（约658-659行）：
```python
current = await self.task_service.get(task_id)
if current.state in {TaskState.FAILED, TaskState.TIMEOUT}:
    await self.task_service.transition(task_id, TaskState.QUEUED)
    await self.task_service.transition(task_id, TaskState.RUNNING)
elif current.state == TaskState.QUEUED:
    await self.task_service.transition(task_id, TaskState.RUNNING)
elif current.state == TaskState.RUNNING:
    pass  # 已经是 RUNNING，无需转换
else:
    logger.warning("Seedream fallback skipped for %s (state=%s)", task_id, current.state)
    return None
```

【修改4】review 失败分支（约640-656行）改用最新 retry_count + _retry_or_finalize 统一出口：
当前代码用 task.retry_count（过期快照）和硬编码 3。改为：
```python
else:
    latest = await self.task_service.get(task_id)
    if latest.retry_count < self.settings.auto_retry_limit:
        logger.warning(
            "Master review failed for %s (attempt %s/%s): %s",
            task_id, latest.retry_count + 1, self.settings.auto_retry_limit, review.problems,
        )
        await self._retry_or_finalize(task_id, TaskState.FAILED, error_msg)
    else:
        await self.task_service.transition(task_id, TaskState.FAILED, error=error_msg)
```
（error_msg 用已有的错误消息变量，保持 review 失败的原始逻辑）

【修改5】review 失败后确保 _retry_or_finalize 会 enqueue（确认 _retry_or_finalize 内部已有 enqueue，约155-156行；若 review 分支原本手动 retry 没 enqueue，现在统一走 _retry_or_finalize 即可）
